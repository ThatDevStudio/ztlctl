    Add new design sections to DESIGN.md for v3.0 features. Per IDOC-02, these must document the architectural decisions for recall, contradiction, and ingestion.

    Insert new sections BEFORE the Decision Log (Section 19) and Implementation Backlog (Section 20). Renumber those sections accordingly.

    New sections to add:

    **Section 19: Session Recall** (new)
    - RecallService with three query modes: temporal (date range + per-session topic summary), topic (text search across session history), topology (session-to-session connectivity via shared content)
    - MCP resource `ztlctl://sessions/recent` for agent context loading
    - Design choice: recall queries session metadata and logs, not note content — separation of session state from knowledge artifacts

    **Section 20: Contradiction Detection** (new)
    - ContradictionService with candidate pair discovery: shared topic + high vector similarity + decision note type filter
    - Heuristic scoring: negation patterns, key_points comparison
    - Confirmation flow: user confirms → `contradicts` graph edge recorded
    - MCP resource `ztlctl://review/contradictions` for agent review
    - Design choice: contradiction is advisory (candidates surfaced, human confirms) — the system never auto-resolves contradictions

    **Section 21: Ingestion Pipeline** (new)
    - IngestService: normalize external input → feed into CreateService create path (single durable write path invariant preserved)
    - TranscriptionService: local whisper/faster-whisper, 11 format support (mp3, m4a, wav, mp4, ogg, flac, mkv, webm + txt, vtt, srt)
    - Two-phase workflow: `captured` reference created by ingestion, agent annotates to `annotated` status
    - MediaIngestConfig in `[ingest.media]` TOML section
    - Design choice: transcription is local-only — no audio data leaves the machine

    **Section 22: Polaris and Methodology** (new)
    - Polaris: persistent priorities document in `garden/groves/polaris.md`, MCP resource `ztlctl://polaris`, `check_alignment` action
    - Context assembly integration: polaris content injected as Layer 1 (operational state)
    - Methodology: prose-as-title convention, title quality check in `CAT_STRUCTURAL` at info severity
    - Design choice: `check_alignment` is advisory — `aligned` is always true, agent uses polaris context for reasoning

    Renumber existing Section 19 (Decision Log) → Section 23, Section 20 (Implementation Backlog) → Section 24.

    Each section should follow the existing DESIGN.md style: brief overview, key types/interfaces, invariants if any, cross-references to other sections.
