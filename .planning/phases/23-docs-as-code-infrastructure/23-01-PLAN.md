  <action>
Add a new `doc_lint` job to `.github/workflows/pr-ci.yml` at the same level as `validate_pr` (both are top-level jobs, running in parallel — no `needs:` dependency between them).

Insert the following job AFTER the `validate_pr` job block:

```yaml
  doc_lint:
    name: Doc Lint
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - name: Check out repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Set up uv
        uses: astral-sh/setup-uv@v3
        with:
          enable-cache: true

      - name: Sync dev dependencies
        run: uv sync --group dev

      - name: MkDocs build (strict)
        id: mkdocs_build
        run: uv run mkdocs build --strict

      - name: Vale prose lint
        id: vale
        uses: vale-cli/vale-action@v2.1.1
        with:
          fail_on_error: true
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: pymarkdownlnt
        id: pymarkdown
        run: uv run pymarkdown --config .pymarkdown.json scan --recurse docs

      - name: Doc lint summary
        if: ${{ always() }}
        run: |
          cat >> "$GITHUB_STEP_SUMMARY" <<EOF
          ### Doc Lint summary

          | Gate | Result |
          | --- | --- |
          | MkDocs build (strict) | ${{ steps.mkdocs_build.outcome }} |
          | Vale prose lint | ${{ steps.vale.outcome }} |
          | pymarkdownlnt | ${{ steps.pymarkdown.outcome }} |
          EOF
```

CRITICAL: Do NOT add `-v` flag to `mkdocs build --strict` — confirmed MkDocs bug suppresses strict-mode failures with -v. The step must use exactly `uv run mkdocs build --strict`.

CRITICAL: Use `vale-cli/vale-action@v2.1.1` (not `errata-ai/vale-action@v2`) — the org migrated.

The `doc_lint` job must NOT have a `needs: [validate_pr]` key — both jobs run in parallel by default when neither references the other.
